# Angular: Environment, Config & SitecoreClient

This document captures the design decisions and implementation steps for environment variable handling, `sitecore.config.ts`, and `SitecoreClient` injection in the Angular sample and package.

---

## 1. Problem

Angular does not expose `process.env` at build time the way Next.js does. The Sitecore SDK packages (`@sitecore-content-sdk/content`, `@sitecore-content-sdk/core`) read `process.env` in several places:

- `content/src/config/define-config.ts` — `SITECORE_EDGE_CONTEXT_ID`, `SITECORE_API_KEY`, `SITECORE_API_HOST`, `SITECORE_EDITING_SECRET`, `PERSONALIZE_MIDDLEWARE_*_TIMEOUT`
- `core/src/tools/resolve-edge-url.ts` — `SITECORE_EDGE_PLATFORM_HOSTNAME`, `SITECORE_EXPERIENCE_EDGE_HOSTNAME`
- `core/src/tools/utils.ts` — `JSS_ALLOWED_ORIGINS`

In SSR (Node), `process.env` is available at runtime. In the browser bundle, it is not. We need a build-time mechanism to capture env vars into the Angular app so they can be passed into `defineConfig()` and ultimately into `SitecoreClient`.

---

## 2. Environment generation (`scripts/generate-environment.ts`)

### Design

- A TypeScript script (`scripts/generate-environment.ts`) run via `tsx` before build/serve.
- Accepts `--dev` or `--prod` flag to determine which output file to generate.
- Uses `dotenv` to load `.env` files into `process.env`, then reads values from `process.env` only.

### Env file layering (priority)

1. **Real `process.env`** (e.g. CI/deployment platform env vars) — highest priority, never overridden.
2. **Mode-specific file** (`.env.dev` or `.env.prod`) — overrides values from `.env`.
3. **Base `.env`** — loaded first with `override: false`.

### Generated files

- `src/environments/environment.dev.ts` — generated by `--dev`, used in Angular `development` config.
- `src/environments/environment.prod.ts` — generated by `--prod`, used in Angular `production` config.
- Both are **gitignored**. Only the placeholder `src/environments/environment.ts` is committed.

### Supported env var names

All canonical names the SDK packages read (no `NEXT_PUBLIC_*` variants):

| Env var | Maps to |
|---------|---------|
| `SITECORE_EDGE_CONTEXT_ID` | `sitecore.edgeContextId` |
| `SITECORE_EDGE_CLIENT_CONTEXT_ID` | `sitecore.edgeClientContextId` |
| `SITECORE_EDGE_PLATFORM_HOSTNAME` | `sitecore.edgePlatformHostname` |
| `SITECORE_EXPERIENCE_EDGE_HOSTNAME` | `sitecore.experienceEdgeHostname` |
| `SITECORE_API_KEY` | `sitecore.apiKey` |
| `SITECORE_API_HOST` | `sitecore.apiHost` |
| `SITECORE_EDITING_SECRET` | `sitecore.editingSecret` |
| `SITECORE_DEFAULT_SITE` | `sitecore.defaultSite` |
| `SITECORE_DEFAULT_LANGUAGE` | `sitecore.defaultLanguage` |
| `SITECORE_PERSONALIZE_SCOPE` | `sitecore.personalizeScope` |
| `PERSONALIZE_MIDDLEWARE_EDGE_TIMEOUT` | `sitecore.personalizeEdgeTimeout` |
| `PERSONALIZE_MIDDLEWARE_CDP_TIMEOUT` | `sitecore.personalizeCdpTimeout` |
| `JSS_ALLOWED_ORIGINS` | `sitecore.jssAllowedOrigins` |

## 3. Angular fileReplacements

In `angular.json`, both configurations use `fileReplacements`:

- **production**: swaps `environment.ts` → `environment.prod.ts`
- **development**: swaps `environment.ts` → `environment.dev.ts`

This ensures the correct generated file is bundled for each mode.

## 4. `sitecore.config.ts`

Located at the project root. Imports `environment` (which gets swapped at build time) and passes values into `defineConfig()`:

```typescript
import { defineConfig } from '@sitecore-content-sdk/angular';
import { environment } from './src/environments/environment';

const sc = environment.sitecore;

export default defineConfig({
  api: {
    edge: {
      contextId: sc.edgeContextId,
      clientContextId: sc.edgeClientContextId || undefined,
      edgeUrl: sc.edgePlatformHostname || undefined,
    },
    local: {
      apiKey: sc.apiKey,
      apiHost: sc.apiHost,
    },
  },
  editingSecret: sc.editingSecret || undefined,
  defaultSite: sc.defaultSite,
  defaultLanguage: sc.defaultLanguage || 'en',
  personalize: {
    scope: sc.personalizeScope || undefined,
    edgeTimeout: sc.personalizeEdgeTimeout ? parseInt(sc.personalizeEdgeTimeout, 10) : undefined,
    cdpTimeout: sc.personalizeCdpTimeout ? parseInt(sc.personalizeCdpTimeout, 10) : undefined,
  },
});
```

## 5. `package.json` scripts

Uses `npm-run-all2` (`run-s`) for sequential execution and `tsx` to run TypeScript scripts:

| Script | What it does |
|--------|-------------|
| `gen:env` | `tsx scripts/generate-environment.ts` (requires `--dev` or `--prod`) |
| `gen:env:dev` | Generates `environment.dev.ts` from `.env` + `.env.dev` |
| `gen:env:prod` | Generates `environment.prod.ts` from `.env` + `.env.prod` |
| `start` | `run-s gen:env:dev start:app` |
| `build` | `run-s gen:env:prod build:app` |
| `watch` | `run-s gen:env:dev watch:app` |
| `serve:ssr` | `run-s build serve:ssr:app` |

## 6. `provideSitecoreAngular` — config and client injection

### Tokens (in `packages/angular/src/lib/tokens.ts`)

| Token | Type | Purpose |
|-------|------|---------|
| `SITECORE_CONFIG_TOKEN` | `InjectionToken<SitecoreConfig>` | The resolved config object |
| `SITECORE_CLIENT_TOKEN` | `InjectionToken<SitecoreClient>` | A `SitecoreClient` instance |
| `NOT_FOUND_ROUTE_TOKEN` | `InjectionToken<string>` | Route path for 404 page |
| `ERROR_ROUTE_TOKEN` | `InjectionToken<string>` | Route path for 500 page |

### Provider function (in `packages/angular/src/lib/providers.ts`)

When `sitecoreConfig` is passed to `provideSitecoreAngular()`:

1. Provides the config via `SITECORE_CONFIG_TOKEN`.
2. **Eagerly** creates `new SitecoreClient({ ...sitecoreConfig })` and provides it via `SITECORE_CLIENT_TOKEN`.

This mirrors the Next.js pattern where `src/lib/sitecore-client.ts` creates a singleton client from the config.

### Usage in components/services

```typescript
import { inject } from '@angular/core';
import { SITECORE_CLIENT_TOKEN, SITECORE_CONFIG_TOKEN } from '@sitecore-content-sdk/angular';

// In a component or service:
const scClient = inject(SITECORE_CLIENT_TOKEN);
const scConfig = inject(SITECORE_CONFIG_TOKEN);

// Use the client
const page = await scClient.getPage('/some-path');
```

### App wiring (`app.config.ts`)

```typescript
import scConfig from '../../sitecore.config';

export const appConfig: ApplicationConfig = {
  providers: [
    provideSitecoreAngular({
      sitecoreConfig: scConfig,
      notFoundRoute: '/404',
      errorRoute: '/500',
    }),
    // ... other providers
  ],
};
```
