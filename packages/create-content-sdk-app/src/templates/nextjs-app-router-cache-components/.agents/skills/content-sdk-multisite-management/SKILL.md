# Content SDK Multisite Management (App Router + Cache Components)

Site resolution from request (e.g. hostname or cookie); proxy rewrites to /[site]/[locale]/...path. **Locale must run before multisite** so next-intl and multisite see the correct locale. Cache Components does not affect proxy behavior — caching happens inside the page, not in middleware.

## When to Use

- User asks about multiple sites, hostnames, or site resolution.
- Task involves .sitecore/sites.json, multisite config, or proxy/middleware for site.
- User mentions "multisite," "site resolution," "hostname," or "sites.json."

## How to perform

- Site list: `.sitecore/sites.json`. Proxy logic lives in `src/proxy.ts`; ensure `src/middleware.ts` re-exports it if present. Keep chain order: PreviewProxy → BotTrackingProxy → LocaleProxy → AppRouterMultisiteProxy → RedirectsProxy → PersonalizeProxy. Exclude API (including `/api/revalidate`), `_next`, and static assets in the matcher.

## Hard Rules

- Site list is in `.sitecore/sites.json` (typically generated by Sitecore CLI or deployment). Avoid hand-editing unless the format is known.
- **Proxy:** Implemented in `src/proxy.ts`. Next.js runs middleware from `middleware.ts` at root or in `src/` — if the app only has `proxy.ts`, add `src/middleware.ts` that re-exports it.
- **Chain order is fixed:** PreviewProxy → BotTrackingProxy → LocaleProxy → AppRouterMultisiteProxy → RedirectsProxy → PersonalizeProxy. **Do not change this order.** PreviewProxy authorizes preview first; LocaleProxy must run before multisite so i18n and multisite see the correct locale. AppRouterMultisiteProxy rewrites to /[site]/[locale]/[...path].
- **Matcher:** Exclude API routes (including `/api/revalidate`), `_next/`, sitemap, robots, healthz, Sitecore paths, and static assets so the proxy stays lightweight.
- Config: sitecore.config.ts → multisite, redirects, personalize. Single SitecoreClient; pass resolved site and locale from route params into the cache helpers (`getSitecorePage`, `getSitecoreDictionary`) and into preview calls.
- Sites are also passed to `createSitecoreRevalidateRouteHandler` (in `src/app/api/revalidate/route.ts`) so dictionary tags are computed correctly during webhook revalidation.

## Stop Conditions

- Stop if the user wants to reorder the proxy chain; explain that LocaleProxy must run before AppRouterMultisiteProxy for App Router and PreviewProxy must run first.
- Stop if sites.json format is unknown and the change could break resolution; suggest checking SDK docs or CLI output.
- Do not add a second site resolution mechanism; use the existing proxy and config.
